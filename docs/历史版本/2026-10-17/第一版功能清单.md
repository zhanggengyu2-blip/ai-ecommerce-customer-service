# 第一版功能清单

本清单将[已确认产品定义](./第一版产品定义.md)拆成可核对的功能，不代表已经完成开发，也不按条目数量计算完成率。业务职责见[业务流程](./第一版业务流程.md)，操作响应见[功能流程](./第一版功能流程.md)，源码依据见[功能来源对照](./第一版功能来源对照.md)。

**来源：** 现有＝AgentServe 有主体实现；改造＝已有基础但目标行为不同；新增＝尚无目标能力，可复用既有服务或记录；待验证＝外部能力尚未证明。现有功能仍需统一角色、租户适配和验证，HelpPilot 参考能力不算已经融合。

**验收编号：** 验收① AI 实际解决常规咨询；验收② 人工接续完整可用；验收③ 真实接入与跨店隔离。以下编号是功能索引，不是开发顺序或独立任务实体。

## 6. 明确不纳入第一版

| 不做项 | 保留的必要能力／处理方式 |
| --- | --- |
| 独立任务、方案审核／同意 AI 决策 | 多订单同事件，人工统一接入并回复；有可靠结果和选填备注 |
| 轮询派单、转接、名额上限和占位计算 | 全部在线客服共享待接，同会话唯一接入保护 |
| 工作台执行淘宝退换货审批或支付赔付 | 客户在淘宝申请，客服在淘宝后台办理；本产品做查询、指引、沟通和记录 |
| 完整电商／ERP 后台 | 保留接待所需查询，不迁移商品、订单、支付、库存管理业务 |
| 租户运营、自助注册、跨店切换／迁移页面 | 产品方内部开通；跨店退出再登录，特殊换店联系产品方 |
| 路由条件／流程画布、任意接口地址 | 预置只读目录、维护知识场景、限定已适配模型 |
| 多版本历史管理、Prompt 自助恢复 | 知识仅上一版恢复；Prompt 找回联系产品方；历史回答快照仍保留 |
| 会话内新建完整引用面板 | 保留提问路由分析及原有简要知识来源折叠 |
| 整次服务评价、数据面板、充值和套餐后台 | 单条 AI 回复反馈保留；数据面板需求在核心闭环完成后讨论 |

## 7. 验证边界与后续设计

- 外部待验证：淘宝准入与授权、真实消息和业务查询、图片／卡片、开窗招呼、客户主动结束与原生人工事件、淘宝反馈入口，以及模型角色兼容性。
- 集成待验证：跨店数据和配置隔离、并发唯一接入、失联／正常换端区别、迟到草稿及安抚取消、程序填入后的原生撤销。它们是目标行为的验证要求，不新增独立产品模块。
- 页面后续细化：页面结构、状态文案、政策问卷具体题目及必要的接回／恢复入口。接口、数据变更和开发拆分另行整理，不通过本清单暗增范围。

第一版是否完成，按已确认三条验收判断；真实淘宝目标不因本地模拟可用而降格。后续发现平台限制，记录证据和受影响功能编号，再讨论处理方式。
