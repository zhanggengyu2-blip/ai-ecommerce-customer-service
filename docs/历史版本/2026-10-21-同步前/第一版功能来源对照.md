# 第一版功能来源对照

最近变更：[2026-10-21 前端调整确认](./前端调整确认-2026-10-21.md)。重开会话、AI 摘要、商品规格、回复路由及 Score 以该记录为准。

更新日期：2026-10-19。与[功能清单](./第一版功能清单.md)采用相同模块顺序。

核对对象为 `app/` 中的 AgentServe 主工程副本，来源提交 `781975f7ca6cfff9ba6afefcd669f47a0fdd7f28`。下表说明能复用什么、还要补什么，不代表目标功能已经实现或通过验收；HelpPilot 参考能力不算已经融合。

- **原有**：AgentServe 已有主要实现，保留并做必要适配。
- **调整**：有现成基础，但需要修改页面、范围或规则。
- **新增**：没有本版要求的完整能力，可以复用原有服务实现。

## 模块一：客服中心

| 子模块 / 功能 | 来源 | 当前基础与本版变化 |
| --- | --- | --- |
| 会话列表、消息、人工接入、发送与完结 | 原有＋调整 | 已有会话状态、按最新消息排序和人工操作；补本版三栏布局、AI 阶段提示、名称与共享规则 |
| 同一会话仅一名客服接入 | 原有 | 已有按等待且未接入条件完成的唯一接入保护，仍需保留和验证 |
| 在线客服共享等待、等待时 AI 继续回答 | 调整＋新增 | 原版按平台账号范围展示等待队列；等待状态不会继续调用 AI，需调整，并补在线资格和同次求助复用 |
| 300 秒安抚、5 分钟 AI 完结、30 秒断线补位 | 新增 | 原版没有本版约定的完整时间规则及取消迟到提示机制 |
| 人工接入后的 AI 回复辅助 | 新增 | 原版人工接待不持续生成内部建议；需补输入框生成、关闭、失败恢复及防止覆盖人工文字 |
| 会话独立草稿 | 调整 | 原界面使用单一草稿，需按客服和会话分别管理 |
| 同一聊天框新建人工事件 | 调整 | 原版关闭会话拒绝新消息，需补完结后默认 AI 和人工重新发起规则 |
| 相关订单、图片及卡片展示 | 原有＋调整＋新增 | 订单查询与详情有基础；会话侧聚合、客户图片及卡片展示按本版补齐 |
| 待办事项及七类客服工单 | 新增 | 原版没有本版订单诉求工单及全店待办表。PendingAction 是客户确认后的业务动作，不等于客服工单 |
| 两个手动创建入口和 AI 自动建单 | 新增 | 需补订单、客户、会话关联，类型及诉求内容，重复识别处理和同店共享 |
| 待完成／已完成人工标记 | 新增 | 需补完成客服和时间；不关联退款、物流等业务进度，也不通过标记改变电商数据 |
| 历史会话及单条回复路由入口 | 原有＋调整＋新增 | 已有会话、消息与路由记录；补只展示已完结会话、同店跨客服历史入口及对应提问跳转 |
| 会话 Token 汇总 | 调整＋新增 | 已有模型调用和追踪基础；补按会话汇总路由、回答及辅助用量，排除知识导入和独立测试 |

依据：[人工会话与唯一接入](../app/backend/app/api/v1/support.py)、[客户接待和操作确认](../app/backend/app/api/v1/customer.py)、[会话及待确认动作](../app/backend/app/models/conversation.py)、[接待编排](../app/backend/app/services/orchestrator.py)、[原会话界面](../app/frontend/src/AdminConversations.vue)。

## 模块二：电商管理

| 子模块 | 来源 | 当前基础与本版变化 |
| --- | --- | --- |
| 客户管理 | 原有 | 客户新增、资料编辑、进入客户会话可复用；默认地址与订单收货信息含义保持分清 |
| 商品管理 | 原有 | 商品新增、编辑、上下架、库存调整可复用 |
| 订单管理 | 原有 | 订单创建、查询、支付、发货、取消和申请退款入口可复用 |
| 支付记录 | 原有 | 已有订单支付和退款金额、状态记录 |
| 物流管理 | 原有 | 已有发货、物流状态更新及详情 |
| 退款售后 | 原有 | 已有整单全额退款申请、审批、退货验收和完成退款。不能把七类诉求记录标成七类业务执行都已具备 |
| 库存流水 | 原有 | 已有库存占用、释放、出库、退货回库和人工调整记录 |

本版保留这些原有业务入口；工单不增加处理按钮，不扩展部分退款、换货、补发及订单改址等执行能力。当前客户档案地址编辑不能直接视为订单地址修改；原发货记录也不能直接当作换货或补发物流。

依据：[电商业务](../app/backend/app/services/eshop.py)、[电商页面与操作](../app/backend/app/api/v1/eshop.py)、[电商资料结构](../app/backend/app/models/eshop.py)、[原有电商页面](../app/frontend/src/views/eshop)。

## 模块三：AI 与知识

| 子模块 / 功能 | 来源 | 当前基础与本版变化 |
| --- | --- | --- |
| 对话、向量化与重排序调用 | 原有 | 已有三类模型调用及相关配置，不能将三类模型整体算成新增 |
| 店铺模型和 Key 配置 | 调整 | 原版主要从服务器读取凭据，需补按租户维护、遮挡显示、已适配模型选择及本店共享 |
| 配置验证及整店 AI 接待启用 | 调整＋新增 | 保留模型调用与故障兜底基础，补配置可用性验证和整店人工启用；不与会话内回复辅助开关混为一项 |
| 知识库、客服知识、知识切片组织 | 调整＋新增 | 已有文档、版本、切片、标签及适用范围；补知识库分类及说明，与页面层级相连 |
| 自动用途说明及渐进筛选 | 新增＋调整 | 当前不是完整的“先看知识库及用途，再找切片”流程，需补元信息和筛选；不能只新增分类页面就算已完成 |
| 上传、解析、切片、向量化与检索 | 原有 | 已有多种资料解析、手动切片、向量化、关键词及向量检索、融合与重排，优先复用 |
| 每篇知识独立分段及预览 | 调整＋新增 | 原版有分段处理参数，需补按篇设置和左右预览交互 |
| 直接发布及离开丢弃未提交内容 | 调整 | 原版处理和发布分步存在；前台不增加草稿按钮，未发布内容不能进入正式接待 |
| 知识有效时间 | 原有＋调整 | 沿用生效、失效过滤，统一作用于当前知识检索，保留记录 |
| 恢复上一版且保留有效时间 | 调整 | 原版可选择多个历史版本，恢复会清空失效时间；需要按本版限制并修正 |
| 独立召回测试及 AI 回答 | 原有＋调整 | 现有测试返回切片，需补完整回答、连续追问、当轮切片和正式业务隔离；测试只用已发布有效知识 |
| 完整业务 Prompt 编辑 | 原有 | 已有读取和保存模板，继续保留全文编辑；不另加试问按钮 |
| 固定平台基础规则 | 调整＋新增 | 当前部分 system 内容来自可编辑模板；需把平台服务范围和操作边界单独维护 |
| 增强语义判断 | 调整 | 已有规则与 LLM 分类，需减少关键词对复杂业务意图的直接控制，保留程序校验及故障兜底，不整体改成 ReAct |
| AI 参考相关历史聊天 | 调整＋新增 | 原路由只带本次有限历史，知识回答不直接带完整历史；需按租户、客户和相关事件取用，避免把已存聊天当作完整记忆能力 |

依据：[资料及检索](../app/backend/app/services/knowledge.py)、[有效版本](../app/backend/app/services/knowledge_lifecycle.py)、[切片处理](../app/backend/app/services/knowledge_editor.py)、[发布及版本恢复](../app/backend/app/api/v1/knowledge.py)、[路由](../app/backend/app/services/routing.py)、[模型分类](../app/backend/app/providers/routing.py)、[配置及模板](../app/backend/app/api/v1/configuration.py)。

## 模块五：平台设置与通用能力

| 子模块 / 功能 | 来源 | 当前基础与本版变化 |
| --- | --- | --- |
| 店铺接入资料 | 原有＋调整 | 已有平台账号管理，收敛为一个租户、一个平台、一家店铺；不将资料维护视为所有渠道能力已完成 |
| 客服账号 | 原有＋调整 | 账号创建及停用可复用；店铺端从多角色改为统一客服 |
| 接待规则 | 新增，复用部分原逻辑 | 展示本版固定时长和规则，已有人工手动完结等逻辑保留 |
| 自动打招呼 | 新增 | 补开关、固定文案及发送一次的条件，不调用 LLM |
| 检索设置 | 原有＋调整 | 原版有部分全局检索配置；补本店 Top K、必填 Score（默认 0.30），并移入平台设置页签 |
| 多租户及同店共享 | 调整 | 已有租户字段和部分数据范围，但认证等路径仍有固定租户限制；须逐项核查，不能当作完整隔离已经具备 |
| 手动在线／离线 | 新增 | 原账号启停与连接状态不等同于客服工作状态，需要补业务判定 |
| 同账号单一有效接待端 | 新增 | 原登录令牌不具备完整的新端接替、旧端失效规则 |

依据：[账号与角色](../app/backend/app/api/v1/users.py)、[认证与隔离](../app/backend/app/core/security.py)、[平台账号](../app/backend/app/api/v1/accounts.py)、[配置](../app/backend/app/api/v1/configuration.py)。

本表用于说明复用和改动范围，不按行数估算完成率或工期。“原有”仍需适配店铺范围及统一客服角色，并按本版验收标准核对。旧版对照保留在[历史版本](./历史版本/2026-10-17/第一版功能来源对照.md)。
