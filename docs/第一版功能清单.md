## 模块一：客服中心

帮助客服接待客户、记录售后诉求，并查看之前聊过什么。

### 1.1 会话工作台

页面分成三栏：左侧会话列表，中间聊天区，右侧先展示相关订单，再展示客服工单，两部分用分割线隔开。

| 功能 | 说明 | 来源 |
| --- | --- | --- |
| 查看会话列表 | 按客户保留唯一入口，展示该客户当前或最近接待的状态。等待接入有醒目标识；列表行高度一致，按最新消息排序，列表顶部不重复展示“会话”及客户数量 | 调整 |
| 接入客户 | 本店在线客服都能看到待接会话。先接入的人负责本次聊天，其他人不能再次接入或代其发送；不轮询、不转接、不限制接待名额 | 原有＋调整 |
| 查看聊天内容 | 按原顺序展示客户、AI 和客服的消息；人工接入处增加分割提示，保留之前与 AI 的聊天内容。客户仍在同一个聊天框内交流 | 原有＋调整 |
| 接收图片及卡片 | 展示客户提供的图片、商品卡片或订单信息。图片辅助核实问题，看不清时继续确认；有关数据按实际可取得内容展示 | 调整＋新增 |
| 使用 AI 回复辅助 | 人工接入后，AI 的建议进入客服输入框。生成时暂时不能输入，但可以随时关闭 AI；生成完成后可修改、清空或直接发送，由客服决定是否发给客户 | 新增 |
| 关闭或重新开启辅助 | 关闭时保留已有文字并恢复编辑；失败时也能手动回复。迟到的生成结果不能覆盖人工输入。需要重新生成时关闭后再开启，不增加“采纳”或独立重新生成按钮 | 新增 |
| 切换会话 | 各会话的输入草稿、辅助开关互不影响；本接待端切回来能继续编辑。不要求关闭页面或换设备后恢复草稿 | 调整 |
| 查看相关订单 | 在右侧查看订单号、商品、规格、数量及当前状态，打开订单详情。存在多笔订单时分别展示 | 原有＋调整 |
| 查看及新增客服工单 | 右侧展示本次会话的售后诉求记录和完成标记。手动创建前先确定订单，进入表单后客户、订单、会话不能修改 | 新增 |
| 查看历史会话 | 打开当前客户以往的会话记录，不再限制必须由同一名客服接待。没有历史会话时隐藏入口 | 原有＋调整 |
| 完结及重新发起 | 人工完结前弹窗确认，取消保留输入；确认只完结弹窗对应接待。客户之后再发消息默认 AI；重新发起固定新建人工接待，追加分割线，旧记录与旧工单独立保留，客户入口不重复 | 原有＋调整 |
| 等待及断线处理 | 等待人工期间 AI 继续处理能够回答的内容；超过 300 秒安抚一次。实际断线超过 30 秒由 AI 补位，恢复后客服明确接回 | 调整＋新增 |
| AI 接待异常 | Key 或模型服务不可用时显示提醒，人工仍可接续；复用本次等待，不反复请求人工。消息发送本身失败时不能提示已经送达 | 原有＋调整 |

### 1.2 待办事项

统一收录本店 AI 和客服创建的工单。这里的“工单”是**针对一个订单记录的一次售后诉求**，不是人工接入请求，也不负责执行退款等业务操作。

| 功能 | 说明 | 来源 |
| --- | --- | --- |
| 查看全店工单 | 本店客服共同查看工单编号、客户、关联订单、诉求类型、诉求说明、创建来源和创建时间 | 新增 |
| 按完成情况查看 | 使用“待完成”“已完成”两个页签，默认打开待完成；新工单默认待完成 | 新增 |
| 自动创建 | 客户明确提出办理诉求、订单也已确定时，AI 整理内容，系统核对后创建。仅咨询规则不自动建单；同一次诉求的补充不重复建单 | 新增 |
| 手动创建 | 先选择一次当前或历史会话，选项显示人工接待中、AI 接待中、等待接入或已完结；自动带入客户，再选择该会话中的一笔订单。切换会话清空原订单 | 新增 |
| 填写诉求 | 选择七类售后诉求，填写涉及的商品、数量和说明；根据需要补充金额、换货目标或新收货信息。支持一张工单记录同一订单内不同商品的不同诉求 | 新增 |
| 查看及修改 | 查看完整工单，补充或修正诉求内容。创建后保留关联客户、订单和会话，修改内容不会更改完成标记 | 新增 |
| 标记已完成 | 客服在待办列表中手动标记，记录完成客服和时间，工单移入已完成页签；会话右侧同步显示 | 新增 |
| 查询与返回原会话 | 按客户、订单、工单编号、诉求类型及创建日期查询；“会话记录”打开与历史共用的详情抽屉，可继续打开回复路由弹窗，关闭后保留来源页筛选及位置；订单详情独立查看 | 新增 |

七类诉求为：**取消订单、仅退款、退货退款、换货、修改收货地址、补发、其他售后**。部分退款通过金额、商品和数量说明，不单独增加第八类。

例如：客户本次要处理两笔订单，分别建两张工单；同一订单里一条裤子退货、另一条换码，可以在一张工单中分别说明。同一订单日后出现新的售后事件，可以再次建单。

**完成标记只表示客服确认这条诉求已经处理。** 工单不提供退款审批、换货发货等按钮，不跟踪业务进度，也不因为标记完成而修改订单、支付、库存或物流。会话完结不会自动完成工单。

### 1.3 历史会话记录

| 功能 | 说明 | 来源 |
| --- | --- | --- |
| 查看已完结会话 | 展示本店全部已完结会话，包括纯 AI 接待和不同客服接待的记录 | 原有＋调整 |
| 查询会话 | 按客户名称或会话编号查找，客户与会话 ID 分列，查看接待客服、开始及结束时间；日期控件支持整框点击及清空 | 原有＋调整 |
| 主要咨询内容 | 会话结束后由 AI 生成一句话摘要；未生成或失败如实提示，不拿首条消息代替摘要 | 新增 |
| 查看详情 | 入口文案“查看完整会话”，打开共用抽屉，按原顺序查看聊天内容和已有信息来源；中性浅灰背景区分白色消息，历史详情以查看为主 | 原有＋调整 |
| 查看回复路由 | 客户某条提问有 AI 处理记录时，提供“查看回复路由”，打开对应详情；没有记录的消息不展示该入口 | 新增，复用现有路由详情 |
| 查看 Token 用量 | 展示输入、输出和合计 Token。统计本会话产生的路由、回答、回复辅助等调用，未发送的辅助建议也计入；知识导入、独立召回测试和会话摘要调用不计入本会话 Token 总量；摘要调用单独留存用量。服务商未返回用量时显示“—”，不冒充零消耗 | 调整 |

## 模块二：电商管理

本版查看和维护本地业务数据库中的商品、订单及相关记录，AI 的订单查询也读取这些本地数据；暂不接入淘宝订单接口。保留 AgentServe 原有业务操作入口，工单完成标记与这里的真实操作结果分别管理。

### 2.1 客户管理

| 功能 | 说明 | 来源 |
| --- | --- | --- |
| 客户列表与资料 | 查看客户名称、联系方式、地址及关联身份，只编辑已有资料，移除人工“新增客户”入口 | 原有 |
| 进入客户会话 | 从客户记录进入对应聊天界面 | 原有＋调整 |
| 客户备注 | 由客服手动填写、全店共用，不自动生成，不与商品业务补充知识混用 | 新增 |
| 区分地址用途 | 修改客户档案地址不代表已经修改某笔现有订单的收货地址，页面应表达清楚 | 原有规则保留 |

### 2.2 商品管理

| 功能 | 说明 | 来源 |
| --- | --- | --- |
| 商品列表 | 一件商品一行，展示图片、名称和规格数量；售价取首个创建规格，不展示价格区间，不随库存或上下架情况改取其他规格 | 原有＋调整 |
| 新增商品 | 上方填写名称、可选图片，下方增删规格行；至少一个规格，规格名不重复，各自填写售价和非负整数初始库存；图片支持 JPG／PNG／WebP，不超过 5 MB | 调整＋新增 |
| 商品详情及规格 | 查看各规格的售价、可用及预占库存与状态，支持新增规格、编辑和上下架；公共商品信息与具体规格分别管理 | 调整＋新增 |
| 调整库存 | 选择具体规格，填写变动数量和原因，记录到对应规格流水；不能出现负库存，不能把全部规格合成一份库存 | 原有＋调整 |

### 2.3 订单管理

| 功能 | 说明 | 来源 |
| --- | --- | --- |
| 查看订单 | 查看客户、商品明细、数量、金额、订单及物流状态；打开详情查看相关支付、物流和售后记录 | 原有 |
| 创建订单 | 选择本店已有客户、具体商品规格及数量，按该规格价格核对金额和收货信息；订单与库存始终关联原规格 | 原有 |
| 支付、发货、取消 | 保留原有操作，按订单当前情况展示可以执行的按钮；操作成功后同步相关记录 | 原有 |
| 提交退款申请 | 保留从订单发起退款申请的入口，进入退款售后流程；申请提交成功不等于退款完成 | 原有 |

### 2.4 支付记录

查看支付编号、关联订单、支付金额、退款金额和状态，并可打开相关订单。沿用原有支付记录管理，不增加充值、套餐或平台计费后台。**来源：原有。**

### 2.5 物流管理

查看物流单号、承运方、关联订单、当前状态和物流详情，保留原有物流更新操作。只展示或更新当前业务实际支持的物流记录。**来源：原有。**

### 2.6 退款售后

| 功能 | 说明 | 来源 |
| --- | --- | --- |
| 查看退款售后记录 | 查看售后编号、订单、金额、原因、退货信息和当前状态 | 原有 |
| 审核申请 | 保留同意、驳回入口；根据原有业务规则继续办理 | 原有 |
| 退货验收及完成退款 | 保留退货验收、填写退货单号和完成退款等操作；业务记录更新后再显示结果 | 原有 |

本模块先沿用原版已有办理流程。七类工单的建立不意味着同时增加七套业务执行流程；部分退款、换货等诉求可以完整记录，工单本身不扩展这里的操作能力。

### 2.7 库存流水

查看商品及具体规格、库存变动、变动原因、操作人和时间。下单占用、发货、取消、退货入库等按原有业务操作记录，人工调整也需要留下原因。**来源：原有。**

## 模块三：AI 与知识

配置 AI 使用的模型，并维护它回答问题时可以参考的资料。

### 3.1 AI 模型配置

| 功能 | 说明 | 来源 |
| --- | --- | --- |
| 配置三类模型 | 对话推理负责理解和回答；向量化帮助查找意思相近的资料；重排序帮助把更相关的资料排在前面 | 原有＋调整 |
| 配置服务商、模型和 Key | 对话服务商限定 DeepSeek、百炼千问；展示已适配的模型。三类模型可以共用 Key，也可以分别填写 | 调整 |
| 验证配置 | 检查模型连接及配置是否可用，失败时说明原因；首次缺少 Key 不能显示已经可用，编辑不换 Key 时保留原值 | 调整＋新增 |
| 全店共用 | 一个店铺维护一组上述配置，本店所有客服共用。Key 安全保存，保存后遮挡显示，不明文回显，也不写入普通日志 | 调整 |
| 配置说明 | 分别说明全店共用、对客自动接待和人工内部建议；关闭时在三张模型卡片上方提示“完成以下三个模型的配置，即可开启 AI 自动接待”，该提示不能代替真实连接验证 | 调整 |
| 启用 AI 接待 | 模型及必要资料准备后，由客服手动启用本店 AI 接待；与单个会话的回复辅助分别控制，不要求必须有客服在线才能启用 | 新增 |

### 3.2 知识库

知识库相当于资料分类，例如平台政策、店铺政策、售后处理、投诉反馈。每个知识库下面可以放多篇客服知识。

| 功能 | 说明 | 来源 |
| --- | --- | --- |
| 查看及维护知识库 | 展示名称、用途说明和知识数量，支持新增、编辑；仍有知识的分类不能直接删除 | 调整＋新增 |
| 分类内的操作 | 知识篇数与“查看知识”放在一起；“新增知识”直接打开编辑页并预选当前分类 | 调整 |
| 展示预置内容 | 初始分类及资料可以看到，也按正常知识方式维护；不另建一套隐藏场景目录 | 调整 |
| 帮助 AI 找资料 | AI 可结合知识库说明和资料用途缩小查找范围，再检索具体知识切片；信息不足时扩大查找或追问，不只依赖标题关键词 | 调整＋新增 |

### 3.3 客服知识

| 功能 | 说明 | 来源 |
| --- | --- | --- |
| 查看知识列表 | 展示名称、所属知识库、用途说明、文件信息、解析及向量化情况、有效时间和创建信息 | 原有＋调整 |
| 新增或更新资料 | 选择知识库、填写名称和正文，或在正文卡片上方拖拽／选择文件；每次单个、不超过 2 MB，限 UTF-8 纯文本 MD、MARKDOWN、TXT、CSV、TSV、JSON、YAML、YML、XML、LOG；支持上传新版本，PDF／Word 不属于本轮上传范围 | 原有＋调整 |
| 自动生成用途说明 | 系统根据正文生成用途说明，新建时不显示；进入已有知识的详情和编辑时，可以查看和修改 | 新增 |
| 独立设置分段 | 每篇知识分别设置分隔符、分段长度和重叠长度。左侧设置、右侧预览，点击明显可见的“预览分段”后才展示“切片 1、切片 2”等；修改正文或参数后重新预览 | 调整＋新增 |
| 直接发布 | 不增加保存草稿按钮，也不要求先召回测试。未提交的修改离开后不保留；已发布内容才供正式接待使用 | 调整 |
| 设置有效时间 | 生效及失效时间都可不填；不填则长期有效。问号点击展开说明，日期支持整框点击及清空。到期停止参与当前检索，保留内容和历史消息，不自动恢复旧版 | 原有＋调整 |
| 查看及维护详情 | 查看文件信息、用途说明、知识切片，调整有效时间、启停或重新向量化 | 原有＋调整 |
| 恢复上一版 | 只提供恢复上一已发布版本，保留该版本原有生效和失效时间，不自动变成长期有效 | 调整 |

平台政策、店铺政策、场景处理指引、商品业务补充均作为知识内容维护，第一版不另做商品备注专用表单、店铺政策问卷或独立预置场景目录。

| 编辑业务模板 | 默认只读，点击“编辑”后修改完整文本，保存后供后续调用使用；取消或离开丢弃未保存内容。编辑有误或需要找回原文时联系平台，不新增自助多版本恢复页 | 原有 |
| 保留基础规则 | 客服服务范围和业务操作边界由平台底层维护；店铺业务模板不能开放越权操作。无关问题礼貌引导回商品、订单和售后 | 调整＋新增 |

模板编辑页不增加试问按钮；测试统一从召回测试进入。AI 对业务意图的理解以语义判断为主，系统仍核对订单、工具及操作权限；第一版不整体改成自主循环执行的 ReAct。

## 模块五：平台设置

同一页面通过五个页签切换。本店客服共用这些设置。

### 5.1 店铺接入

本版展示当前平台标识、店铺资料及“未接入”状态；淘宝消息接收、淘宝订单查询及其授权连接延后，相关入口仅提供说明，不触发外部授权或显示已连接。一个租户对应一个平台、一家店铺、多个客服；第一版不做自助换店、多店切换或公开注册页面。租户及初始账号由平台内部开通。**来源：原有＋调整。**

### 5.2 客服账号

| 功能 | 说明 | 来源 |
| --- | --- | --- |
| 查看及开通账号 | 查看本店客服名称、登录账号、在线情况和启停状态，开通新客服账号；支持上传 JPG／PNG／WebP 头像，不超过 2 MB | 原有＋调整 |
| 启用及停用 | 沿用原版停用规则，停用会阻止登录、接入及回复等受保护操作；历史记录继续保留 | 原有 |
| 统一角色 | 店铺端只有客服角色，不另分商家、管理员、知识运营等店铺角色 | 调整 |

### 5.3 接待规则

展示固定规则，不提供时长自定义：

- AI 已回答、没有等待人工时，客户最后一条消息后 5 分钟无新消息，结束本次 AI 会话并轻提示。
- 等待人工超过 300 秒安抚一次，仍保留待接会话；有人接入后取消迟到提示。
- 实际连接中断保留 30 秒重连机会，仍未恢复时由 AI 补位。
- 人工接待由客服手动完结；无消息不会自动完结。
- 所有在线客服共享等待项，只有一人能够接入；手动离线仍可处理已有会话。
- 工单完成情况由客服标记，和会话结束分别管理。

**来源：原有规则保留＋调整＋新增。**

### 5.4 自动打招呼

配置开关和固定欢迎语，默认关闭，需要时手动开启。客户打开聊天但没有发消息时，同次会话发送一次；已有人工接待时不插入，不调用大模型。**来源：新增。**

### 5.5 检索设置

统一设置本店的 Top K 和 Score。Top K 表示最终提供给回答参考的切片数量，默认 5、范围 1–10；Score 表示最低相关度，必填，默认 0.30，范围 0–1。含义、范围及校验错误放在对应输入框旁，不另加独立“必填”标签；空值、非数值和越界不能保存。分段长度、重叠长度和分隔符仍按每篇客服知识设置，这里不重复维护。**来源：原有＋调整。**

## 全店通用规则

1. 一个租户就是一家店铺。订单、客户、会话、工单、知识和配置不能跨店混用。
2. 同店共用知识、配置、订单、待办和历史记录；会话负责人、客服在线状态和输入草稿分别管理。
3. 同一客服账号同一时刻只有一个有效接待端，新设备接替后旧端不能继续接待；不做跨店快捷切换。
4. AI 回答要区分查询到的事实、处理建议和已完成的操作，不能只凭聊天内容宣称退款、换货或补发已经完成。
5. 原版已有取消订单和申请退款的客户确认流程继续保留；工单创建、工单完成标记和业务操作分别管理。
6. 其他模块不增加轮询派单、转接、名额上限、独立方案审核、工单业务执行、整次服务评价或计费后台。

## 统一页面与视觉规则

- 采用灰白底、炭黑与深灰文字、靛蓝按钮及选中状态；绿色、黄色、红色继续表达成功、等待、错误。浮层、抽屉、图表与正文采用同一主题。
- 页面标题与说明由公共顶部栏承载；新增、创建放在卡片筛选区右侧，编辑、保存和发布放进对应卡片。新增与编辑知识的顶部标题同步变化。
- 店铺名点击进入店铺接入，侧栏 AI 状态与店铺名对齐并进入模型配置；顶栏不重复店铺名。
- 下拉采用统一组件，日期支持整框点击与清空，窄屏使用可展开的完整导航；操作和辅助说明清晰可读。
- 使用正常产品文案，不展示开发阶段提示；待授权、缺失快照、配置验证失败等真实状态如实呈现。
