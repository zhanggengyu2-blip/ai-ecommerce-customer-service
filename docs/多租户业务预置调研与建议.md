# 多租户业务预置：官方资料调研与第一版建议

调研日期：2026-10-16。用户已确认统一网站、多商家分别登录并按租户隔离，并采纳“预置基础内容，商家补充后启用”。本文件保留官方资料、调研时的建议及限制；预置类别已确认，具体文案、数值和页面形式待细化。未进行真实店铺授权、接口联调或功能开发；调研三平台不等于第一版同时交付三平台。

后续范围确认：第一版实际先接淘宝，保留更多商家与其他平台扩展。一个租户、一个平台、一家店铺、多个客服，同一商家跨店或跨平台分别使用不同租户；平台基础资料与商家补充资料均按所属租户及绑定平台/店铺适用。

## 1. 调研结论

新租户可以获得已有接待能力和基础资料，不必从空白提示词、空白知识库开始。适合提供通用接待模板、按平台整理的基础资料及商家信息填写模板；实际承诺由商家补充，当前业务结果通过授权接口查询。下述产品取舍为 AI 建议，不是电商平台对第三方应用的授权承诺。

| 平台 | 官方资料支持的事实 | 对本产品的启示（AI 整理） |
| --- | --- | --- |
| 淘宝 | 《消费者保障服务协议》区分基础保障与商家选择的特色承诺，包括发货、破损补寄、退货等；客服面板文档列有商品、活动知识库 | 提供基础政策资料及承诺填写模板，具体发货、补寄与退货承诺由商家确认，不给所有店铺套相同答案 |

## 2. 建议第一版提供的业务预置

| 预置内容 | 平台方提前提供什么 | 租户还需要做什么 |
| --- | --- | --- |
| 五类售后场景 | 未收到、退货退款、换货、破损/质量、错发/漏发的处理骨架 | 补充自己的例外政策；沿用已确认人工决策边界 |
| 信息收集模板 | 核实相关订单、商品/规格、数量、主要诉求；按问题收集必要图片等资料 | 不要求商家自行设计每个追问；有现成信息不重复询问 |
| 工单模板 | 主要诉求、相关商品及数量、事实和证据、AI 建议、待审核动作、处理结果 | 客服审核或修改；同一事件混合退换仍是一张工单 |
| 常用话术初稿 | 固定招呼、核实信息、等待人工、人工暂未接入、处理进度说明等文案 | 确认店铺称呼、语气和承诺；开关与触发仍遵循既有接待规则 |
| 对应平台基础资料 | 我们整理的政策摘要、官方来源、适用范围、生效/核查日期 | 补充商家政策；不能降低适用的强制保障 |
| 常见问题框架 | 怎么查物流、怎么申请退换、退款进度怎么看等问题结构 | 补充本店真实条件；不预填未经核实的到账和发货时间 |
| 接待协作默认规则 | 既有空闲优先、同等轮询、人工接入后 AI 仅出草稿等已确认行为 | 配置人员和必要容量/等待时长；不要求商家搭流程，不默认开放全部规则编辑 |
| 店铺资料引导 | 售后政策可选问答、条件说明及自由补充入口；Markdown 可选导入 | 选择或补充本租户真实约定，允许跳过；商品业务备注另用轻量表单 |

所有新模板均为本系统整理编写，不声称直接复制平台原生答案库。行业模板可后续补充，例如服装尺码信息或商品使用说明的填写框架；不把泛化行业常识当作某件商品事实，不在首版顺带建设行业流程编辑器。

后续用户已确认合作商家为服装品类，并采纳可选轻量表单。备注最新定位为商品关联的业务补充，例如预计补货、临时发货安排，而非主要补录商品属性。客服在知识库选择商品范围及填写业务备注，AI 商品查询与会话商品卡片共用；提交后本租户生效、保留作者/更新时间、管理员可维护或停用已确认。商品信息仍以授权接口为主要来源，库存实时查询、预计安排保持预计；商家政策按最新要求通过可选售后问答及自由补充建立，Markdown 作为可选导入。

## 3. 预置、商家确认和实时查询的分界

- 可预置：处理步骤、问题分类、信息清单、工单字段、基础文案和经核查的平台资料。
- 商家确认：店铺身份、客服人员、退货收件信息、自己的服务承诺、商品知识及活动内容。能授权读取的内容可预填，但须说明来源，不能假设接口一定可取；退货指引优先采用该订单/售后单有效指定地址，不能无条件套用店铺默认地址。
- 实时查询：库存、物流轨迹、订单状态、退款状态及当前允许执行的动作。预置“怎么查、怎么解释”，不预置查询结果。

示例：客户说“退两件”。系统可按模板定位商品和数量、查售后状态、整理工单；是否适用无理由、运费责任、是否已经退款，仍需结合商品承诺和订单结果。不能发出“填完单号一定退款”或“所有商品均可无理由退”的统一承诺。

资金和实物操作沿用已确认边界：本系统退款、退换和补发仍由人工决定/执行。电商平台自身的自动处理可能已经发生，不能把内部待审批当作平台资金尚未变动。原生端已有人工或自动接待时，模板不得绕过既有暂停/去重规则插话；原生欢迎功能存在，也不能证明第三方能收到未发消息前的开窗事件。

## 4. 租户开通后的建议体验

选择并授权已支持的平台 → 自动带入该平台资料和通用售后模板 → 补充/核对店铺政策、收件信息、人员及 AI 配置 → 预览欢迎语和几条示例回答 → 启用已验证的接待能力。

这是业务初始化建议，尚未确认必须增加独立向导页面。可以直接利用现有设置页，以待完善项目提示承接。示例预览仅用于检查配置，不替代真实授权和消息收发验证。

平台基础资料由我们维护，随租户绑定的平台选用，避免商家重复搜集；商家政策按租户独立建立，最新采用可选售后问答及自由补充，Markdown 为可选导入。租户补充资料只作用于本租户，不改写其他租户的商家政策或公共平台规则。通用话术升级不覆盖租户已修改的文案；政策变化分别核查适用范围和生效日期，不能因为保留旧模板而继续使用过期规则。更新方式与界面留待细化，不默认为自动抓取或自动发布。

租户只维护自己的业务资料及已开放的配置，不通过配置任意放宽平台限制，不自行编排接口，也不默认新增 AI 自动审批开关。平台能力缺失或必需信息缺失时，应明确显示待完善/需人工核实，不能以通用模板伪造成功接入或实际承诺。

## 5. 用户已确认的模块范围

用户已采纳第一版预置平台基础资料、五类售后信息收集与处理骨架、常用话术、工单模板、FAQ 框架及已确定的协作默认行为；租户补充必要的店铺资料后启用，平台基础资料由产品方维护；按最新要求，商家售后政策问答可跳过，不以填完整份商家政策作为启用的强制前提。具体内容和页面形式留到交互细化，不随此项扩展完整行业模板市场、流程设计器、自动退款权限或电商后台。

商家政策引导的最新已确认约束：填写前用大白话解释用途；题量少、全部选填、必要时给实际案例；选项尽量提供“其他＋文字补充”。具体题目后续研究，不要求租户先完成整份问答才能使用。

## 6. 淘宝商家与软件提供方分别准备什么（2026-10-18 核查）

用户询问作为淘宝商家是否需要预先开通账号。本节为官方资料核查及基于当前 SaaS 方案的职责建议，不代表已取得应用准入或客服消息权限。

- 店铺使用者：按第三方 SaaS 方案，使用已有淘宝店铺账号向获准应用授权，不要求每个店铺自行注册开发者、创建 AppKey。首次授权优先由店铺主账号操作；子账号使用应用须有主账号授予的相应权限。淘宝授权凭证按店铺独立，与本产品客服账号和商家自带 AI Key 区分。
- 软件提供方：通过淘宝开放平台生态伙伴入驻、按“应用软件开发商”等实际适用身份及类目申请，创建应用并申请需要的能力。具体归类和审核应以当前控制台及官方答复为准，不能把创建应用当作所有接口已经开放。
- “商家后台系统自研”不是本项目服务多店铺的默认通道。官方该类目文档面向有开发能力的天猫卖家，明确普通淘宝集市卖家不支持该通道，应用只供自己的店铺使用；不能据此建议普通淘宝店直接申请自研 AppKey，或借商家自研身份服务无关店铺。
- 商品／订单查询与客服消息接入分别核实。官方有客服工具的专门类目规则，但查得规则页更新时间为2022年，其具体规模门槛不能直接视为2026年所有AI客服接入方案的统一条件。当前能申请的类目、实时消息收发、原生人工事件、测试授权条件仍需控制台／官方确认。

官方依据：[用户授权介绍](https://developer.alibaba.com/docs/doc.htm?articleId=102635&docType=1&treeId=1)、[应用软件开发商接入指南](https://developer.alibaba.com/docs/doc.htm?articleId=120867&docType=1&treeId=779)、[商家后台系统应用](https://developer.alibaba.com/docs/doc.htm?articleId=101564&docType=1&treeId=512)、[客服工具类目管理规则](https://developer.alibaba.com/docs/doc.htm?articleId=105705&docType=1&treeId=253)。

## 7. 用户已完成开发商入驻，下一步核对客服类目（2026-10-18）

用户明确已入驻为应用软件开发商。此状态为用户提供；不再把开发商入驻作为尚未办理的前置任务，也不据此认为已获得应用、AppKey或聊天权限。

官方接入指南的下一步为“开发—创建应用”，按业务选择“商家经营工具”，再提交相应类目的方案与资质申请。当前产品自动接待更接近“客服机器人”；“客服面板插件”主要提供千牛／旺旺内的接待辅助区域，不能把插件类目或界面出现当作独立网页客服已获实时消息收发能力。

需要核对官方资料的时间差：2022-10-08更新的招商表仍将客服机器人标为不开放招商；2024-06-14更新的机器人类目规则定义其服务淘宝、天猫商家，并规定2024-07-01生效，但未据此明确新服务商现在可申请。因此，不能断言目前完全开放或永不开放，须看用户控制台类目状态，必要时由用户通过支持中心询问当前准入。机器人、面板插件的新规则也不能直接与2022旧版通用客服工具规模门槛混为同一规则。

下一步优先查看实际类目选择及条件，确认接收／回复买家聊天、店铺授权及业务查询的适用能力，再安排对应应用申请和真实联调。未提交任何申请、订购或授权，也未操作合作运营店铺。

新增官方依据：[客服机器人类目规则](https://developer.alibaba.com/docs/doc.htm?articleId=121757&docType=1&treeId=253)、[客服面板插件类目规则](https://developer.alibaba.com/docs/doc.htm?articleId=121758&docType=1&treeId=253)、[商家经营工具开放招商类目（2022年页面）](https://developer.alibaba.com/docs/doc.htm?articleId=121029&docType=1&treeId=779)、[客服面板插件开发指引](https://developer.alibaba.com/docs/doc.htm?articleId=119210&docType=1&treeId=780)。
