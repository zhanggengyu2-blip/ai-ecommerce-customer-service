# 二次开发基底与融合建议

状态：用户已确认 AgentServe 为主工程、选择性吸收 HelpPilot。主工程工作副本已建立于 app/；具体融合与业务改造尚未完成。接下来结合已确认需求与源码做差异澄清。

用户已采纳本文选型方向。参考工程及旧原型保留；主工程基线与后续差异见《AgentServe 主工程差异清单》。

## 1. 推荐结论

以 AgentServe 作为主工程与应用基底，选择性吸收 HelpPilot 的 AI 能力和评测方法；产品与数据围绕一套流程组织。融合的是能力，不是同时运行两个完整客服系统。

AgentServe 的接口、工作台、知识内容维护和运行记录更贴近目标产品；HelpPilot 的价值集中于有界的工具推理循环、回答核验、人工确认后恢复的思路，以及基于案例的评测。单纯保留 AgentServe 现有固定业务分支，不等于已经获得 HelpPilot 的工具推理能力；把 HelpPilot 整套挂进 AgentServe 又会带入重复的模型配置、检索、业务状态和发送逻辑。

## 2. 业务层怎样结合

| 能力 | 主体及建议 |
| --- | --- |
| 客服工作台、会话、消息、权限及知识管理 | 以 AgentServe 为应用基础，按已确定的接待、派单、历史展示规则改造 |
| AI 常规问答及业务查询 | 使用统一的分流入口，保留 AgentServe 的事实查询/知识检索分工；确定的常规查询走清楚的固定流程 |
| 复杂咨询的信息调查 | 借鉴 HelpPilot：模型根据上一步结果选择下一项允许的查询，设置次数/时间上限，缺信息时补问，不能可靠解决则求助人工 |
| AI 回答质量 | 借鉴 HelpPilot 的依据及操作真实性检查；明确哪些检查可由代码完成，哪些回复值得额外模型复核，不强制每句话都增加一次模型调用 |
| 人工客服会话及处理记录 | 使用一套业务记录；人工接入不等于平台业务审批，AI 运行暂停也不等于客户聊天结束。第一版独立任务模块已取消 |
| 质量验证 | 借鉴 HelpPilot 评测方法，重建服装售后、中文表达、政策范围、多订单及多租户案例；旧英文模拟场景和报告数字不能当作本项目效果 |

示例：客户说“这条裤子没收到，现在还能退吗”。统一 AI 流程按需确认订单、查询物流、检索适用售后约定，再解释可确认的结果；物流争议等需人工事项附上已知事实、依据及待决定问题。人工接入后仍由客服决定发送建议，不因采用新基底改变发言权限。

执行分工现已由用户确认：客户在淘宝 App 发起申请，客服在淘宝后台审批；本版工作台不通过 API 执行退换货业务审批。多步骤查询也不需要恢复客服可见的“任务管理”。

## 3. 代码层怎样结合

建议保留 AgentServe 的 API 和应用服务作为外层。重构其 AI 编排入口，把 HelpPilot 值得保留的工具推理/核验逻辑迁入同一内部 AI 服务；无须以独立的 HelpPilot 后端或 Streamlit 页面接在旁边。

内部 AI 服务接收当前租户及会话上下文、调用该租户模型所需的配置、允许的工具和适用知识来源，返回回复草稿、依据、查询结果或人工求助原因。它不再直接调用旧 SQLite、发送消息或擅自执行退款。身份及租户由服务端认证确定，不由模型生成；Key 不放进提示词或普通日志。

| 原有部分 | 结合方式 |
| --- | --- |
| AgentServe routing / orchestrator | 改为统一业务入口，决定常规分支、复杂查询及人工求助；不与 HelpPilot triage 重复各分流一遍 |
| HelpPilot solver | 移植有上限的模型选工具循环；工具重新绑定本项目服务，去掉原模拟业务和固定退款条款 |
| HelpPilot reviewer | 改成可复用的回复核验步骤；使用真实检索原文及工具结果，不能仅靠另一个模型保证正确 |
| HelpPilot approval / interrupt | 仅借鉴待决事项与恢复方法；若本版需要跨请求的 AI 中断恢复再引入。暂停范围是具体 AI 运行，不能阻塞整个客户会话；批准后重查状态和权限 |
| HelpPilot 模型适配 | 可借鉴已有 DeepSeek/千问调用与错误提示，重构为按租户显式传配置；对话角色可共用模型；最新已撤销每租户单 Key，改为按用途独立模型配置，Key 可复用或分开 |
| 检索及存储 | 优先复用 AgentServe 的知识来源、版本及检索接口，运行中保持一个权威知识体系；不再同时维护 HelpPilot 固定 KB_DOCS + Chroma 和另一套知识库 |
| 会话与执行状态 | 会话、负责人及实际业务结果由同一应用持久化；如采用 LangGraph，checkpoint 仅作 AI 执行快照，不能变成第二套客服会话和审批事实 |
| 留痕与评测 | 用统一的调用标识关联 AI 过程、引用及实际动作；将 HelpPilot 评测改接新服务，替换案例与预期，不要求沿用原 LangSmith 作为额外必选服务 |

LangGraph 是实现手段，不是融合前提。可以先抽取工具调用与核验逻辑；只有状态图和跨请求恢复确实解决本版问题时，再作为内部 AI 编排实现引入。不要为沿用框架而照搬原五节点流程。

## 4. 必须认识的改造成本

AgentServe 不是已完成的多租户电商 SaaS：当前身份校验限定租户 1，模型凭据来自服务端统一设置；真实淘宝授权/消息/订单尚未接通。最新已确认改为在线客服共享等待、并发唯一接入、300秒知识库安抚，取消轮询和转接；这些能力及异常离线补位、人工回复建议、图片和卡片仍需适配与验证。

HelpPilot 同样不是可以直接复制的生产级 Agent 引擎：其工具读写演示 SQLite，订单查询未带本项目租户和归属校验，退款返回模拟结果；检索使用固定文档集合，原审批与出回复流程也不是本产品已经确认的业务流程。旧效果数据不能抵消这些改造。

AgentServe 的 MySQL、检索服务与前后端服务带来比当前小原型更大的部署维护范围。不能把换基底理解为只换界面，或把完整电商台账/数据面板自动带入本版。
