# 第一版验收标准

本版已合并截至 2026-10-21 的已确认变更；对应讨论记录见[前端调整确认](./前端调整确认-2026-10-21.md)。本文正文与配套验收标准共同维护当前规则，不再依赖单独的变更记录覆盖旧正文。

更新日期：2026-10-21。按[功能清单](./第一版功能清单.md)的模块顺序检查。以下是目标行为，不表示已经验收通过；本地前端检查只证明当前示例交互及显示，后端持久化、真实模型、并发和隔离须分别验证；本版不验收淘宝消息接收、淘宝订单查询及其授权／同步；详情见[前端预览边界](../app/FRONTEND_PREVIEW.md)。

整体按三件事判断：AI 能有依据地接待；人工与工单流程能连贯使用；本店共享及跨店隔离正确。

## 模块一：客服中心

### 1.1 会话工作台

| 检查场景 | 通过标准 |
| --- | --- |
| 打开不同会话 | 消息、订单和工单对应当前客户及接待；同一客户在列表仅有一个入口，按最新消息排序，单纯完结不改变顺序；列表不重复展示“会话”和客户数量 |
| 完结确认与取消 | 取消保留草稿且不调用完结；确认只处理弹窗绑定的接待。期间切换客户或另一端已改变接待时，不误关当前另一段会话 |
| 两名客服同时接入一个等待项 | 只有一名成功，另一名得到提示，不能代其发送；没有轮询、转接或名额限制 |
| 等待期间继续发消息 | AI 仍能回应可确认事项，本次人工求助不重复；满 300 秒最多安抚一次，等待记录保留 |
| 刚接入时旧安抚任务到达 | 不发送迟到提示，不插入人工正在进行的回复 |
| 人工接入 | AI 历史完整、阶段分隔清楚，客户仍在同一聊天框；AI 建议只进入内部输入框 |
| 生成中关闭辅助或生成失败 | 输入框恢复编辑，已有内容保留，迟到结果不覆盖手动输入 |
| 修改并发送 AI 建议 | 发出的是客服确认的最终文字，显示客服身份；没有自动代发或额外“采纳”步骤 |
| 切换两段会话 | 草稿、辅助开关及接待归属不串用；关闭页面或换设备不要求恢复旧草稿 |
| 模型不可用及恢复 | 工作台提示异常，人工仍可接续，本次等待不反复创建；恢复后不抢回人工会话，发送失败不冒充已送达 |
| 客户没有／有历史 | 前者隐藏历史入口，后者能查看本店该客户的历史，包括其他客服和纯 AI 接待记录 |
| 人工长期无消息、纯 AI 无消息 | 人工只手动完结；纯 AI 已回答且无人工等待，客户空闲 5 分钟后结束并轻提示 |
| 完结后再咨询、人工重新发起 | 再咨询默认 AI；未结束仍归当前客服。重新发起固定新建人工接待，追加分割线，旧接待和旧工单独立保留；重复提交不新增第二条活动接待，客户入口不重复 |
| 图片或卡片到达 | 能展示对应内容；图片不清楚时继续核实，不把猜测当作实际业务结果 |

### 1.2 待办事项与客服工单

| 检查场景 | 通过标准 |
| --- | --- |
| 客户只是问规则 | 不自动创建工单；明确办理且订单已确定后才创建 |
| 同次诉求重复补充 | 原记录得到补充，不因为每条消息重复建单；订单后续新事件仍允许另建 |
| 多订单或同订单混合诉求 | 不同订单分别记录；同一订单可按商品记录退货、换货等多个诉求，部分金额及数量写清楚 |
| 从会话侧新增 | 先确定订单，再进入只读关联表单；客户、订单、会话不能修改，无订单不能建单 |
| 从待办新增 | 先选当前或历史会话，再选该客户在该会话关联的订单；选项显示各接待状态；切换会话清空原订单，不能串到其他客户 |
| 在待办查看会话与路由 | 与历史共用会话详情抽屉，回复路由在来源页打开弹窗；关闭后页签、筛选、分页及位置保持，关联到具体接待而非客户的另一段历史 |
| 查看和修改 | 本店客服可查看及修正诉求，两个入口同步；已完成记录编辑后仍保留完成标记 |
| 打开待办和标记完成 | 默认待完成，新单也默认待完成；人工标记后进入已完成，保留完成客服和时间 |
| 重复点击完成或会话结束 | 完成记录不重复；会话结束不自动完成工单，标记工单也不自动结束会话 |
| 检查业务数据 | 工单保存、编辑、标记完成均不改变订单、支付、退款、库存和物流；工单里没有业务执行按钮或审批进度 |

### 1.3 历史会话记录

| 检查场景 | 通过标准 |
| --- | --- |
| 查看历史列表和详情 | 全店已完结会话可查询，含纯 AI 和不同客服；客户和会话 ID 分列，入口为“查看完整会话”；消息身份、顺序及本次接待范围正确 |
| 会话咨询摘要 | 会话结束后根据该次真实聊天生成一句话，不拿首条消息替代；等待或失败如实显示，摘要失败不影响完结及历史读取，也不被当作客户消息或已办结业务 |
| 从某条提问查看路由 | 在来源页面打开该条提问的对应详情弹窗，关闭后保留原位置；没有 AI 处理记录的消息不出现无效入口 |
| 核对 Token | 输入、输出与合计口径一致；本会话未发送的辅助调用计入，独立测试、知识导入及摘要调用不计入会话 Token 总量；摘要重试同样排除，摘要用量缺失不影响接待用量完整性，不展示费用金额；服务商未提供用量时显示“—” |

## 模块二：电商管理

| 检查场景 | 通过标准 |
| --- | --- |
| 客户资料和备注 | 没有人工新增客户入口；可编辑本店已有资料，备注手动填写且全店可见，不被 AI 自动覆盖；修改客户地址不代表修改历史订单地址 |
| 新增多规格商品 | 名称与可选图片在上方，规格行可增删且至少一个；规格名不重复，逐规格校验价格及非负整数初始库存；任一规格无效时不留下半件商品 |
| 商品图片 | JPG／PNG／WebP、不超过 5 MB；服务端核验实际文件及归属，错误时不保存无效引用 |
| 商品聚合显示 | 一件商品一行，售价稳定取首个创建规格，不显示区间；新增规格不改取更低价或更有库存的规格；库存汇总可回到具体规格 |
| 规格维护与历史 | 每个规格独立价格、可用及预占库存，库存调整留下原因和流水；已有订单仍引用原规格与成交快照，不因改名、调价或合并显示而串库存 |
| 本地订单与事实查询 | 客服及 AI 从本地业务数据库查询同一订单，数据与规格、库存一致；不调用淘宝接口，本地操作结果不表述为已改变淘宝真实订单 |
| 创建订单并办理已有流程 | 选择具体规格，对象、规格数量、成交价和金额正确，按当前状态提供支付、发货、取消、申请退款等原有操作 |
| 提交及审批退款 | 申请、批准、驳回、验收、完成退款有明确区别；申请提交不提示为资金已退回 |
| 查看关联结果 | 订单、支付、物流及库存流水反映同一次业务操作结果，不出现只改页面标记、其他记录未更新的情况 |
| 重复点击或操作失败 | 不重复支付、退款或变更库存；失败不留下相互矛盾的业务数据 |
| 修改客户档案地址 | 不错误提示为某笔已生成订单的收货地址已修改 |

本模块按原版已有流程验收，不因七类工单存在而要求新增七套执行流程。

## 模块三：AI 与知识

| 检查场景 | 通过标准 |
| --- | --- |
| 配置三类模型 | 服务商及适配模型选择正确，Key 可以共用或分开；本店共用，保存后遮挡显示，不泄露到其他店铺 |
| 验证及启用 AI 接待 | 配置缺失或验证失败不能冒充可用；必要配置就绪后可人工启用整店接待，与会话内辅助分别控制，客服离线不阻止启用 |
| 维护知识库 | 分类名称、说明和知识归属一致；篇数与“查看知识”放在一起，“新增知识”自动预选该分类；有内容的分类不能直接删除 |
| 新增与编辑客服知识 | 新建隐藏用途说明，系统根据正文生成；已有内容可查看、修改说明 |
| 上传正文 | 正文卡片上方支持拖拽／选文件，每次一个、不超过 2 MB；只接受列明的 UTF-8 纯文本格式，非 UTF-8、超限或 PDF／Word 被明确拒绝；发布前不参与正式检索 |
| 有效期控件 | 问号点击可展开说明，时间整框点击且可清空；空值表示未设置，失效时间早于生效时间时阻止发布；清空后回读一致 |
| 设置及预览分段 | 每篇参数独立；进入时右侧没有自动预览，点击后出现；修改正文或参数后重新预览，按“切片 1、切片 2”展示且符合当前设置 |
| 直接发布与离开编辑 | 无保存草稿或强制试问；已发布内容按有效时间供接待使用，离开后未提交修改不保留 |
| 知识到期 | 停止参与当前检索，资料、历史消息及原引用保留；不自动恢复旧内容，不改变接待人或派单状态 |
| 恢复上一版 | 只恢复上一已发布版本，保留其原生效、失效时间，不清空失效时间 |
| 切片编辑及向量化失败 | 成功后按有效时间使用新内容；失败保留原可用内容，列表和知识详情保持一致 |
| 召回测试 | 不要求选范围，仅检索全店已发布有效知识；支持连续提问、清空及查看每轮切片；未提交编辑不参与，Score 展示为相关性得分而非命中率或正确率 |
| 测试判断为转人工或业务办理 | 只展示判断，不向客户发送、不建人工待接或工单、不改电商数据 |
| 编辑业务 Prompt | 默认只读，编辑后可改完整模板，保存后后续调用生效，取消或离开丢弃未保存内容；平台基础服务范围和操作限制不能被业务内容开放 |
| 客户问业务及无关问题 | 业务问题按需查询、检索、追问或求助人工；明显无关内容礼貌引导，不误建工单或请求人工 |
| 核对回答依据 | 实时库存、订单和退款结果来自业务查询；资料冲突或信息不足时不编造承诺；模型理解灵活说法，程序仍核对允许操作 |

## 模块四：分析与反馈

| 检查场景 | 通过标准 |
| --- | --- |
| 切换日期范围 | 卡片、趋势和明细采用页面说明的同一日期规则；无数据和零分母不显示错误比例 |
| 核对会话与 AI 占比 | 仅欢迎语不算有提问；AI 独立占比以已结束的有提问会话为分母，排除曾请求人工或实际人工接待的会话 |
| 核对业务操作成功率 | 查询工具不计入；退款申请成功与退款完成含义分清；工单人工完成标记不影响该比例 |
| 核对工单记录 | 按工单创建日期及当前完成标记统计；多种诉求分布的合计可能超过工单总数，有说明 |
| 核对回答反馈 | 仅客户对单条 AI 回答的评价进入列表，有问题、回答和原因，可回到正确会话及路由；点踩率以已评价回答为分母 |
| 查看待跟进问题 | 按最新会话情况列出原因，人工接入、后续沟通或结束后更新；单凭点踩不会永久保留 |
| 查询回复路由 | 关键词、会话 ID、时间、路线、结果及 AI／上下文／降级／转人工／节点等更多筛选均有效；输入、输出、总 Token 缺失显示“—” |
| 回复路由详情 | 节点时序与流程图、实际请求、原始返回、输入输出、上下文与参数来源、最终回复组成、关联动作与审计均对应同次处理；复制及 JSON 导出可用，缺失快照明确提示，不伪造节点或完整性 |

日期口径：有提问会话数及接待趋势按所选日期新建的会话统计，AI 独立占比只看其中已结束的部分；业务操作和回答评价按发生时间统计。转人工请求及实际接入按对应事件发生时间统计，同一轮等待不重复计数。工单按创建日期筛选并查看当前完成标记。

## 模块五：平台设置与多人使用

| 检查场景 | 通过标准 |
| --- | --- |
| 打开平台设置 | 店铺接入、客服账号、接待规则、自动打招呼、检索设置为五个页签；没有独立检索菜单 |
| 查看店铺及账号 | 平台标识、店铺及账号归属正确，淘宝连接如实显示未接入；无需外部授权即可验证本地接待与电商流程；一租户一平台一家店铺，店铺端只有客服角色，不出现多店快捷切换 |
| 客服头像 | 可上传 JPG／PNG／WebP、不超过 2 MB，保存后账号及接待身份使用同一头像；失败保留已有头像，不可引用其他店铺文件 |
| 开通及停用客服 | 本店能创建、启停客服；停用阻止登录、接入和回复，历史保留 |
| 手动离线与断线 | 手动离线仍可处理已有会话；实际断线保留 30 秒重连，超时 AI 补位，恢复后明确接回 |
| 同账号不同设备登录 | 只有一个有效接待端；新端接替后旧端不能继续接待，不产生双重发送 |
| 自动打招呼 | 默认关闭，手动开启后固定文案生效；同次会话未发消息时只发送一次，有人工接待不插入，不调用模型 |
| 修改检索设置 | 全店共用 Top K（默认 5、整数 1–10）和必填 Score（默认 0.30、0–1）；空值、非数值、无穷值及越界不可保存；错误在字段旁显示，作用于后续检索；每篇知识的分段设置仍独立 |
| 两名不同客服同时使用 | 共享知识、配置、订单、工单和历史正确；输入草稿、在线状态、会话归属和回复身份互不串用 |
| 两个店铺分别使用 | 客户、订单、会话、工单、知识、配置和模型凭据不能相互读取或误用，不能通过更换编号访问另一店铺内容 |

## 通用页面与主题

| 检查场景 | 通过标准 |
| --- | --- |
| 页面外框及按钮 | 标题、说明由公共顶部白色栏承载；新增／创建位于卡片筛选区右侧，保存／编辑／发布位于相应内容卡片；知识编辑状态与顶部标题同步 |
| 统一主题 | 侧栏、页面、聊天区和表头为中性灰白；靛蓝用于操作和选中态；成功、等待、错误保持语义色，下拉、日期、抽屉、弹窗、路由及图表一致 |
| 店铺与状态入口 | 店铺名进入店铺接入，侧栏 AI 状态与店铺名对齐并进入模型配置；顶栏不重复店铺名 |
| 下拉、日期和窄屏 | 下拉一致，日期整框点击及清空可用；桌面与窄屏导航、列表内部滚动、弹窗关闭均能操作，没有页面横向溢出 |
| 文案和真实状态 | 不把本地配置检查描述成接口已连接，不把未授权或缺失快照改写成成功；正常页面不暴露开发阶段提示 |

本清单检查产品行为；具体测试数据、接口顺序和自动化检查在开发阶段另行安排，不在这里展开。
